## Project Overview

This is a groundwater modeling project using MODFLOW 6 (via FloPy) coupled with PEST++ for parameter estimation and uncertainty quantification. The workflow simulates a shallow aquifer system with multiple boundary conditions (GHB packages for streams, springs, and confined areas) and uses iterative ensemble smoothing (IES) for history matching.

## Workflow Execution Order

The scripts must be run in alphabetical order as they form a sequential pipeline:

1. **a_model_setup.py** - Creates the MODFLOW 6 groundwater model
2. **c_parameterization.py** - Sets up PEST++ parameterization using pyemu
3. **d_pest_IES_prior.py** - Runs prior parameter ensemble (no updates)
4. **e_pest_IES_HM.py** - Runs history matching with IES iterations
5. **f_postprocess.py** - Analyzes results and generates plots

### Running the Workflow

```bash
# From the repository root
python scripts/a_model_setup.py
python scripts/c_parameterization.py
python scripts/d_pest_IES_prior.py
python scripts/e_pest_IES_HM.py
python scripts/f_postprocess.py
```

## Key Configuration

All model configuration is centralized in `scripts/setup.py`:
- `MODEL_NAME` - defines the model run directory (e.g., 'local_run2')
- `NREALS_PRIOR` - number of prior realizations (default: 100)
- `NPER` - number of stress periods (default: 4)
- Date ranges, file paths, and parameter bounds

When starting a new model run, copy an existing model directory structure and update `MODEL_NAME` in setup.py.

## Architecture

### Core Modules

- **setup.py** - Central configuration file with all paths, parameters, and constants
- **helpers.py** - MODFLOW output extraction (heads, budgets, fluxes)
- **utils_pest.py** - PEST++ parameterization utilities (multiplier arrays, pilot points, time series)
- **pkg_setup.py** - MODFLOW package setup functions (DIS, GHB, NPF, STO, RCH)
- **f_helpers.py** - Post-processing and plotting functions

### Model Structure

The MODFLOW model uses:
- **DIS**: Single layer (`NLAY=1`), 25m grid resolution
- **GHB packages**: Four separate boundaries for Awanui stream, Poukawa stream, springs, and confined area
- **RCHA**: Spatially varying recharge
- **NPF**: Hydraulic conductivity field
- **STO**: Specific storage (steady-state for periods 0,2; transient for 1,3)

### PEST++ Parameterization Strategy

Uses multi-scale parameterization via pyemu:
1. **Fine-scale grid parameters** (`-fngr` suffix) - cell-by-cell geostatistical fields
2. **Pilot points** (`-pp` suffix) - spatially correlated intermediate scale
3. **Constant multipliers** (`-cn` suffix) - uniform scaling factors

Applied to:
- Hydraulic conductivity (K) layers
- Specific storage (S) layers
- Recharge arrays
- GHB conductances and head offsets
- Time-varying GHB heads with temporal correlation

## Observations and Truth Data

The `truth/` directory contains synthetic "truth" observations:
- `output.sample_heads.truth.csv` - Head observations at sample locations
- `output.GHB_AW_fluxes.truth.csv` - Awanui stream fluxes
- `output.sample_recession_rates.truth.csv` - Recession rate observations
- `output.heads.truth.dat` - Head constraint arrays
- `*.weight.dat` and `*.std.dat` - Observation weights and standard deviations

These are generated by `a_model_setup.py` and used in subsequent PEST runs for synthetic testing.

## PEST++ Execution

PEST++ runs use parallel workers via `pyemu.os_utils.start_workers()`:
- Number of workers = `os.cpu_count()`
- Prior run: `noptmax = -1` (ensemble evaluation only)
- History matching: `noptmax = 11` with iterative reinflation

The template directory is copied for each realization, MODFLOW runs in parallel, and post-processing extracts observations.

## Binary Executables

Platform-specific executables are in `bin/windows/` and `bin/linux/`:
- `mf6` - MODFLOW 6
- `pestpp-ies` - PEST++ iterative ensemble smoother
- Other PEST++ variants (glm, sen, da, mou, swp, opt, sqp)

Scripts automatically copy the correct binaries based on OS detection (`os.name`).

## Common Issues

1. **Path sensitivity**: The workflow uses relative paths. Always run scripts from the repository root.
2. **Model directory conflicts**: `a_model_setup.py` deletes existing model directories. Ensure you want to overwrite before running.
3. **PEST template regeneration**: `c_parameterization.py` sets `remove_existing=True` for clean PEST setup.
4. **Missing truth data**: `a_model_setup.py` must complete successfully before parameterization steps.
